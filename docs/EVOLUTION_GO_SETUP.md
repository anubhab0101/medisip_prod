# Optional Evolution Go WhatsApp messaging

MediShop sends queued WhatsApp messages through a separately hosted Evolution Go service. Its worker calls the instance-authenticated `POST /send/text` API. Broadcasts remain queued one recipient at a time so MediShop can recheck customer consent and announcement expiry before each send. Receipt links continue to use the isolated receipt service.

## Important limits

Evolution Go uses the WhatsApp Web protocol through `whatsmeow`; it is not the official Meta WhatsApp Cloud API. WhatsApp may restrict connected accounts. The Evolution Go repository also currently requires license activation before the API is operational, and its README says the API returns `503` until activation. Check the project's license/activation terms and hosting needs before committing to it. For production pharmacy messaging, Meta's official Cloud API is the safer option.

Use a dedicated WhatsApp number, message only customers who explicitly consented, keep volumes low, and do not include medicine names or sensitive health details. MediShop records an accepted API response as `SUBMITTED`; it does not yet process delivery/read receipts.

## Run and connect Evolution Go

1. Deploy Evolution Go as its own Docker service using the [official repository instructions](https://github.com/evolution-foundation/evolution-go). It requires Go 1.24+ to build, PostgreSQL for its databases, and persistent storage for its instance/session state. Keep the database and API private to that service and MediShop's worker.
2. Configure Evolution Go's `.env` with `SERVER_PORT`, a strong `GLOBAL_API_KEY`, and valid `POSTGRES_AUTH_DB` and `POSTGRES_USERS_DB` connection strings. Keep message storage disabled unless you have a specific need for it.
3. Start Evolution Go and complete its license activation in the Manager (`/manager/login`) using the API URL and global key. The API will not operate until activated.
4. In the Manager/API, create an instance, connect the dedicated phone by scanning the QR code, and wait until the instance is connected. Save its **instance token**. Use this token for MediShop; do not put the global admin key in MediShop.
5. Check the deployed version's Swagger page at `/swagger/index.html`. Evolution Go's current API specifies `POST /send/text`, an `apikey` header, and a JSON body containing `number` and `text`.

## MediShop environment

Set these in `.env.local` for local testing or on both MediShop staff and worker services in Render. The receipt service does not need these values.

```dotenv
EVOLUTION_GO_SEND_ENABLED=false
EVOLUTION_GO_BASE_URL=http://127.0.0.1:8080
EVOLUTION_GO_INSTANCE_TOKEN=YOUR_INSTANCE_TOKEN
EVOLUTION_GO_ALLOW_PRIVATE_HTTP=false
```

In Render, set `EVOLUTION_GO_BASE_URL` to the private URL of the Evolution Go service, and set the instance token as a secret on `medishop-worker`. If that private URL uses HTTP, set `EVOLUTION_GO_ALLOW_PRIVATE_HTTP=true` on the worker only. Keep the flag false for public URLs, which must use HTTPS. On `medishop-staff`, only the send-enabled flag is required.

Leave `EVOLUTION_GO_SEND_ENABLED=false` while setting up. Once the service is activated, the phone is connected, and the worker can reach its private API, set the flag to `true` on the staff and worker services and restart/redeploy both. Keep `SMS_SEND_ENABLED` independent.

Test with **Messages → Test with my contact** and your own opted-in customer record before sending any broadcast. After saving a bill, staff open it, create the isolated receipt link, and choose **Send by SMS** or **Send by WhatsApp**. The message is queued only if the customer is active and has consented to that channel. The receipt URL is generated by the worker and is never stored in the message job; delivery status appears in Notifications.

If a request times out or Evolution Go returns an ambiguous server response, MediShop marks the outcome `UNKNOWN` and blocks automatic resend. Check the Evolution Go session and sent messages before retrying so a customer does not receive duplicates.
